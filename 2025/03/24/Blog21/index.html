摘要：本文梳理上午考试数据库技术的第三部分，包括分布式数据库分片与分布透明性、数据仓库的四大特点与体系结构、数据挖掘方法、商业智能，以及反规范化、大数据、SQL 语法要点和数据库新技术。

一、分布式数据库

局部数据库位于不同的物理位置，用统一的全局 DBMS 将它们联网管理，就是分布式数据库。其模式层次在全局概念模式之下增加了分片模式和分布模式，再往下是各局部 DBMS 的局部概念模式与局部内模式。

分片方式：

  • 水平分片：把表中的记录按水平方向分别存放在不同地方
  • 垂直分片：把表中的列按垂直方向分别存放在不同地方

分布透明性分为四个方面：

  • 分片透明性：用户或应用程序不需要知道逻辑上访问的表具体如何分块存储
  • 位置透明性：应用程序不关心数据存储物理位置的改变
  • 逻辑透明性：用户或应用程序无需知道局部使用的是哪种数据模型
  • 复制透明性：用户或应用程序不关心复制的数据从何而来

二、数据仓库

数据库长时间运行后数据越来越多，会影响运行效率，而很久之前的数据对某些程序并非必要，删除又可惜，于是把这些数据提取出来保存到另一个数据库，这就是数据仓库。

数据仓库有四大特点：

  • 面向主题：按一定的主题域组织
  • 集成的：数据来自原有分散数据库的抽取、清理、加工、汇总和整理，并消除源数据中的不一致性
  • 相对稳定的：数据主要供决策分析使用，操作以查询为主，进入数据仓库后一般长期保留，很少修改和删除，只需定期加载刷新
  • 反映历史变化：数据包含历史信息，记录企业从过去某一时点到目前各阶段的信息，可用于趋势分析和预测

数据仓库的体系结构包含四个层次：

  1. 数据源：整个系统的数据源泉
  2. 数据的存储与管理：整个数据仓库系统的核心
  3. OLAP 服务器：对分析所需数据有效集成，按多维模型组织，支持多角度多层次分析
  4. 前端工具：报表工具、查询工具、数据分析工具、数据挖掘工具及应用开发工具

数据挖掘的分析方法

  • 关联分析：发现不同事件之间的关联性，即一个事件发生时另一个事件也经常发生
  • 序列分析：发现一定时间间隔内接连发生的事件，这些事件构成具有普遍意义的序列
  • 分类分析：通过分析具有类别的样本特点，得到决定样本属于各类别的规则或方法，需要先给记录赋予标记
  • 聚类分析：按「物以类聚」原理，把本身没有类别的样本聚集成不同的组并加以描述

商业智能 BI

BI 系统包括数据预处理、建立数据仓库、数据分析、数据展现四个阶段。

数据预处理是整合企业原始数据的第一步，包括抽取、转换和加载三个过程，即 ETL；建立数据仓库是处理海量数据的基础；数据分析是体现系统智能的关键，一般采用联机分析处理 OLAP 和数据挖掘两大技术。OLAP 不仅进行数据汇总聚集，还提供切片、切块、下钻、上卷和旋转等多维分析功能；数据挖掘则通过关联分析、聚类和分类等方法建立分析模型，预测企业未来发展趋势；数据展现主要保障分析结果的可视化。

三、反规范化技术与大数据

规范化能防止插入、更新、删除异常和数据冗余，但把表拆得太细会导致查询时需要关联很多表，严重降低查询效率。因此在读写性能优先的场景下会使用反规范化技术，主要手段是增加派生性冗余列、增加冗余列、重新组表、分割表，本质是为提高查询效率而增加冗余，是规范化操作的逆操作。

大数据的特点：大量化、多样化、价值密度低、快速化。

比较维度 传统数据 大数据
数据量 GB 或 TB 级 PB 级或以上
数据分析需求 现有数据的分析与检测 深度分析（关联分析、回归分析）
硬件平台 高端服务器 集群平台

大数据处理系统的特征：高度可扩展性、高性能、高度容错、支持异构环境、较短的分析延迟、易用且开放的接口、较低成本、向下兼容性。

四、SQL 语言要点

SQL 关键字不区分大小写，常用语法：

功能 语法
创建表 create table
主键 / 外键 primary key / foreign key
修改表 / 删除表 alter table / drop table
索引、视图 index、view
查询 select … from … where
分组查询 group by，分组时 select 后的列要适应分组；用 having 附加分组条件
更名 as
字符串匹配 like，% 匹配多个字符，_ 匹配任意一个字符
插入 / 删除 / 修改 insert into … values / delete from … where / update … set … where
排序 order by，默认升序，降序加 DESC
授权 / 收回权限 grant … on … to（可用 with grant option 允许再授权）/ revoke … on … from
其他 with check option 表示检查 where 后的谓词条件；distinct 去重；union 取并；intersect 取交

编写 SQL 的思路：select 之后是要显示的属性列，from 之后是表名，where 之后是查询条件；涉及平均数、最大值、求和等运算必须分组，group by 后跟分组属性列，having 后跟分组条件。条件判断时数字不用引号，字符串必须用单引号。

五、数据库新技术

联邦数据库 FDBS：彼此协作却又相互独立的成员数据库的集合，对各成员数据库按不同程度集成，并对外提供统一接口。特征为分布性、异构性、自治性、透明性。它与分布式数据库的区别是：FDBS 内部各成员数据库互相独立，仅提供对外统一接口；分布式数据库的数据分布在各局部数据库内，内部实际是一个整体。

NoSQL（Not only SQL）是非关系型数据库：

对比项 关系数据库 NoSQL
并发支持 支持并发，效率低 并发性能高
存储与查询 关系表方式存储、SQL 查询 海量数据存储、查询效率高
扩展方式 向上扩展 向外扩展
索引方式 B 树、哈希等 键值索引
应用领域 面向通用领域 特定应用领域

NoSQL 目前的不足：成熟度不够，大量关键特性有待实现；开源产品支持力度有限；对数据挖掘与商务智能支持不足，现有产品无法直接使用；专家少。代表产品有 Redis、MongoDB 等。

内存数据库：抛弃磁盘数据管理的传统方式，基于全部数据都在内存中重新设计体系结构，并在数据缓存、快速算法、并行操作方面做了改进，数据处理速度通常比传统数据库快 10 倍以上。其特点是工作版本常驻内存，活动事务只与实时内存数据库的内存拷贝打交道，常见产品有 Redis、SQLite 等。

数据库性能优化可以从硬件系统（CPU、内存、I/O、网络）、系统软件（进程优先级、CPU 使用权、内存使用等参数）、数据库设计（表的规划、建立物化视图、索引策略——常查询的建索引、常修改的避免索引）和应用软件（用不相干子查询替代相干子查询、只检索需要的列、用带 in 的条件子句等价替换 or 子句、使用数据库连接池、经常提交以尽早释放锁、尽可能减少多表查询）等方面入手。分布式数据库还要考虑全局查询树的变换、多副本策略、通信代价和查询树的分解等。
