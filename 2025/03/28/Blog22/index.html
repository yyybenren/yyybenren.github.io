软考系统分析师-基础知识-网络体系结构与 TCP/IP 协议族

摘要：本文梳理上午考试计算机网络的第一部分，包括 OSI/RM 七层模型各层的功能与协议、各层互联设备、双绞线与光纤等传输介质，以及 TCP/IP 协议族的网络层、传输层、应用层协议与常用端口号。

一、OSI/RM 七层模型

层次 主要功能 典型协议 设备
物理层 包括物理连网媒介，协议产生并检测电压以便发送和接收信号，单位是比特 RS-232、RS-449、V.35、RJ-45 中继器、集线器
数据链路层 控制网络层与物理层之间的通信，把网络层的数据分割成帧，负责物理地址寻址、成帧、流量控制、检错、重发，单位是帧 SDLC、HDLC、PPP、STP、帧中继、IEE802、ATM 交换机、网桥
网络层 把网络地址翻译成对应的物理地址，决定数据如何从发送方路由到接收方，可实现拥塞控制、网际互联，单位是分组 IP、IPX、ICMP、IGMP、ARP、RARP 路由器
传输层 确保数据可靠、顺序、无错地从 A 点传输到 B 点，提供建立、维护和拆除传送连接的功能，提供端到端的错误恢复和流量控制 TCP、UDP、SPX 网关
会话层 在两个节点之间建立和维持通信，提供交互会话管理功能，控制三种数据流方向（一路交互、两路交替、两路同时） RPC、SQL、NFS 网关
表示层 相当于应用程序和网络之间的翻译官，管理数据的解密加密、数据转换、格式化和文本压缩 JPEG、ASCII、GIF、MPEG、DES 网关
应用层 对软件提供接口以使程序能使用网络服务 Telnet、FTP、HTTP、SMTP、POP3、DNS、DHCP 网关

二、各层网络设备

设备 工作层次 主要功能
中继器 物理层 对接收信号进行再生和发送，只用于扩展传输距离，对高层协议透明，但使用个数有限（以太网中只能用 4 个）
网桥 数据链路层 根据帧的物理地址转发，缓解网络通信繁忙度，只能连接相同 MAC 层的网络
路由器 网络层 通过逻辑地址转发，可完成异构网络之间的互联互通，只能连接使用相同网络层协议的子网
网关 高层（4～7 层） 最复杂的互联设备，用于连接网络层以上执行不同协议的子网
集线器 物理层 相当于多端口中继器
二层交换机 数据链路层 传统意义上的交换机，相当于多端口网桥
三层交换机 网络层 带路由功能的二层交换机
多层交换机 高层（4～7 层） 带协议转换的交换机

三、传输介质

双绞线：把多根铜线按规则缠绕在一起以减少干扰，分为无屏蔽双绞线 UTP 和屏蔽双绞线 STP，传输距离在 100m 以内。

UTP 价格低、安装简单但可靠性相对较低，按类别分为 CAT3（10Mbps）、CAT4（无实际应用）、CAT5（100Mbps，用于快速以太网）、CAT5E（1000Mbps）、CAT6（1000Mbps，用于替代 CAT5E）。

STP 比 UTP 增加了一层屏蔽层，可靠性更高，但价格高、安装麻烦，一般用于对传输可靠性要求很高的场合。

光纤由纤芯和包层组成，传输的是光信号，因此需要先把电信号转换为光信号。

类型 光源 特点
多模光纤 MMF 发光二极管 LED 纤芯半径较大，可同时传输多种信号，成本低但效率和可靠性较低，适合短距离传输（100Mbps 时 2km，1000Mbps 时 550m）
单模光纤 SMF 激光二极管 LD 纤芯半径很小，一般只能传输一种信号，成本高但传输距离远、可靠性高，可达 5km

四、TCP/IP 协议族

TCP/IP 协议分四层：应用层、传输层、Internet 层（网络层）、网络接口层，与 OSI 七层存在对应关系。需要重点记忆基于 TCP 和基于 UDP 的应用层协议。

网络层协议

协议 说明
IP 网络层最重要的核心协议，在源地址和目的地址之间传送数据报，无连接、不可靠
ICMP 因特网控制报文协议，在 IP 主机、路由器之间传递控制消息，如网络通不通、主机是否可达、路由是否可用
ARP / RARP 地址解析协议，ARP 把 IP 地址转换为物理地址，RARP 把物理地址转换为 IP 地址
IGMP 网络组管理协议，允许因特网中的计算机参加多播，支持组播

传输层协议

TCP：可靠连接，有验证机制，每发送一个数据包都要求对方回复确认。建立连接采用三次握手：

  1. A 向 B 发送连接请求（SEQ = X）
  2. B 收到后回复确认帧（SEQ = Y，ACK = X + 1）
  3. A 收到确认帧后再发送确认（SEQ = X + 1，ACK = Y + 1），连接建立

其中 SEQ 表示本机发送的数据包序号，A、B 分别计数；ACK = X + 1 表示已收到 A 发送的第 X 个数据包，期望下一个收到第 X + 1 个。

UDP：不可靠连接，数据只管发送不用对方确认，可能有丢包，一般用于视频、音频数据传输。

TCP 保证可靠传输与流量控制的机制：

  • 停止等待协议：发送完一个分组就停止发送，等待对方确认后才发送下一个分组
  • 连续 ARQ 协议：发送方维护一个窗口，窗口中可以有多个分组，窗口大小由接收方返回的 win 值动态决定，采用累积确认的方式，对按序到达的最后一个分组发送确认，从而提高信道利用率
  • 滑动窗口协议：用于流量控制，允许发送方在停止并等待确认前发送多个数据分组，既加速传输又能控制流量

应用层协议

  • FTP：可靠的文件传输协议
  • HTTP：超文本传输协议，用于上网；使用 SSL 加密后的安全网页协议为 HTTPS
  • SMTP 和 POP3：邮件传输协议，邮件报文采用 ASCII 格式
  • Telnet：远程连接协议
  • TFTP：不可靠的小文件传输协议
  • SNMP：简单网络管理协议，必须以管理员身份登录才能完成配置

以 TCP 为基础的 FTP、HTTP 等是可靠传输；以 UDP 为基础的 DHCP、DNS 等是不可靠传输。

DHCP：动态分配 IP 地址协议，客户端可以从 DHCP 服务器获得 DHCP 服务器自身的 IP 地址、DNS 服务器 IP 地址、默认网关 IP 地址等，但拿不到 Web 服务器和邮件服务器的地址。采用客户机/服务器模型，租约默认为 8 天，租约过半时客户机需要申请续租；当租约超过 87.5% 仍联系不上原来的 DHCP 服务器时，开始联系其他 DHCP 服务器。

DNS：把域名解析为 IP 地址。输入网址后先查询本地 DNS 缓存，没有结果再查询本地 DNS 服务器。查询方式有两种：

  • 递归查询：主机提出一次请求，本地服务器自动逐层查询下去，直到找到满足请求的 IP 地址再返回，即问一次得到最终结果
  • 迭代查询：服务器收到一次请求就回答一次，但回答的不一定是最终地址，而是其他层次服务器的地址，客户端再继续去问，直到问到结果

主机向本地域名服务器的查询采用递归查询；本地域名服务器向根域名服务器的查询通常采用迭代查询。
