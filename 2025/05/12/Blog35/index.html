摘要：本文梳理上午考试系统设计的前半部分，包括五种业务流程分析方法、业务流程建模方法、流程表示工具、业务流程重组 BPR 与业务流程管理 BPM，以及五种软件架构风格和两层/三层 C/S、三层 B/S 架构的优缺点。

一、处理流程设计

业务流程分析方法

  1. 价值链分析法：找出或设计出那些能使顾客满意、实现顾客价值最大化的业务流程
  2. 客户关系分析法：把 CRM 用在业务流程分析上。从 CRM 角度看，企业的业务流程应当以客户与企业的关系及客户行为为依据，而不是按企业内部管理来实施
  3. 供应链分析法：源于 SCM，主要从企业内部供应链和外部供应链两个角度分析业务流程，分析哪些流程处于供应链的核心环节
  4. 基于 ERP 的分析法：ERP 的基本思想是把企业的业务流程看作紧密联接的供应链，把供应商、内部采购生产销售以及客户紧密联系起来，实现对企业的动态控制和各种资源的集成优化
  5. 业务流程重组：通过重新审视企业的价值链，从功能成本的比较分析中确定企业具有比较优势的环节，以顾客满意为出发点进行价值链的分解与整合，改造原有业务流程，实现流程最优化

业务流程建模方法

  • 标杆瞄准：以行业领先的标杆企业为目标，结合本企业情况分析建模
  • IDEF：一系列建模、分析和仿真方法的统称
  • DEMO：组织动态本质建模法
  • Petri 网
  • 业务流程建模语言
  • 基于服务的 BPM：基于 Web 服务的思想对业务流程进行建模

流程表示工具

处理流程设计过程中出现了三类用于表示处理流程的工具：

类型 常见工具
图形工具 程序流程图、IPO 图、盒图（N-S 图）、问题分析图（PAD）、判定树
表格工具 判定表
语言工具 过程设计语言

各图形工具的特点：

  • 程序流程图 PFD：用图框表示各种操作，独立于任何一种程序设计语言，直观清晰、易于学习掌握。任何复杂的程序流程图都应由顺序、选择、循环三种结构组合或嵌套而成
  • IPO 图：用来描述构成软件系统的每个模块的输入、输出和数据加工
  • N-S 图：容易表示嵌套和层次关系，具有强烈的结构化特征；但当问题复杂时图会很大，不适合复杂程序的设计
  • PAD 问题分析图：支持结构化程序设计，具有清晰的逻辑结构和标准化图形，能引导设计人员使用结构化程序设计方法，提高程序质量

业务流程重组 BPR

BPR 是对企业的业务流程进行根本性的再思考和彻底性的再设计，从而获得可以用成本、质量、服务和速度等业绩衡量的显著成就。

BPR 的基本原则：以流程为中心的原则、团队管理原则（以人为本）、以客户为导向的原则。

基于 BPR 的系统规划分为：

  1. 战略规划：明确企业战略目标，使信息系统的战略目标与企业战略目标一致
  2. 流程规划：对企业业务流程进行分析，选出关键流程并改进
  3. 数据规划：对业务流程用到的数据进行分类，类似于 BSP，产生不同的数据类
  4. 功能规划：对数据建立 CU 矩阵，对数据的创建和使用建立关系，再对数据总体建立逻辑规划并划分功能模块
  5. 系统实施（实施规划）：制定企业开发目的和项目开发计划

业务流程管理 BPM

BPM 是以规范化的构造端到端卓越业务流程为中心、以持续提高组织业务绩效为目的的系统化方法，采用 PDCA 闭环的管理过程：

  1. 明确业务流程所欲获取的成果
  2. 开发和计划系统的方法实现以上成果
  3. 系统地部署方法，确保全面实施
  4. 根据对业务的检查和分析以及持续的学习活动，评估和审查所执行的方法，并进一步提出计划和实施改进措施

BPM 与 BPR 最根本的不同在于：流程管理并不要求对所有流程进行再造。构造卓越的业务流程并不是流程再造，而是根据现有流程的具体情况对流程进行规范化的设计。流程管理包含三个层面：规范流程、优化流程、再造流程。

二、软件架构设计

架构设计就是需求分配，即把满足需求的职责分配到组件上。软件架构为软件系统提供了结构、行为和属性的高级抽象，由构成系统的元素的描述、这些元素的相互作用、指导元素集成的模式以及这些模式的约束组成。

软件架构的作用：是项目干系人进行交流的手段，明确了对系统实现的约束条件，决定了开发和维护组织的组织结构，制约着系统的质量属性；使推理和控制的更改更加简单，有助于循序渐进的原型设计，可以作为培训的基础；是可传递和可复用的模型，通过研究软件架构可以预测软件的质量。

架构风格

架构设计的一个核心问题是能否达到架构级的软件复用。架构风格反映了领域中众多系统所共有的结构和语义特性，并指导如何将各个构件有效地组织成完整的系统。

五种架构风格：

风格 子类 说明
数据流风格 批处理序列、管道/过滤器 批处理序列一个一个处理，是顺序结构；管道/过滤器是分阶段的数据处理，数据进出管道都要经过过滤器处理，常见于网络数据处理
调用/返回风格 主程序/子程序、面向对象风格、层次结构 层次结构与上下两层关系密切
独立构件风格 进程通信、事件系统 构件之间相互独立，通过消息通信
虚拟机风格 解释器、基于规则的系统 解释器有虚拟机，可仿真硬件执行过程，实现解释执行，效率较低且可跨平台
仓库风格 数据库系统、超文本系统、黑板系统 黑板系统是一个解决方案的数据库，知识源与黑板通信，用于没有确定方案的系统

两层 C/S 架构

客户端和服务器都有处理功能。相比传统集中式架构有不少优点，但现在已不常用，原因是：开发成本较高、客户端程序设计复杂、信息内容和形式单一、用户界面风格不一、软件移植困难、软件维护和升级困难、新技术不能轻易应用、安全性问题、服务器端压力大难以复用。

三层 C/S 架构

把处理功能独立出来，表示层和数据层都变得简单：表示层在客户机上，功能层在应用服务器上，数据层在数据库服务器上，相当于把两层 C/S 架构中的数据从服务器中独立出来。优点有四点：

  1. 各层在逻辑上保持相对独立，系统逻辑结构更清晰，能提高可维护性和可扩展性
  2. 允许灵活有效地选用相应的平台和硬件系统，具有良好的可升级性和开放性
  3. 各层可以并行开发，也可以选择各自最适合的开发语言
  4. 功能层有效隔离表示层与数据层，为严格的安全管理奠定基础，管理层次也更合理可控

三层 C/S 架构设计的关键在于各层之间的通信效率，要慎重考虑三层间的通信方法、通信频度和数据量，否则即使各层硬件能力很强，性能也不高。

三层 B/S 架构

三层 B/S 是三层 C/S 的变种，把客户端换成浏览器，把应用服务器换成 Web 服务器，又称 0 客户端架构。虽然不用开发客户端，但缺点是数据处理能力差：

  • 缺乏对动态页面的支持能力，没有集成有效的数据库处理功能
  • 安全性难以控制
  • 数据查询等响应速度远低于 C/S 架构
  • 数据提交一般以页面为单位，动态交互性不强，不利于 OLTP 应用
