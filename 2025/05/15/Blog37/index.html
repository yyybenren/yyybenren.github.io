软考系统分析师-基础知识-项目管理

摘要：本文梳理上午考试项目管理部分，包括范围管理的五个过程与 WBS 六个层次、进度管理的六个过程与关键路径计算、成本管理的估算方法与挣值分析、质量管理、配置管理的基线版本与变更控制流程，以及风险分类与管理过程。

一、范围管理

范围管理是确定项目的边界（需求），明确哪些工作是项目应该做的，分为五个过程：

  1. 范围计划编制：包括产品范围（软件技术相关）和工作范围（管理相关）。当产品范围发生变化，工作范围必然受影响
  2. 范围定义：定义项目范围，包括产品范围和工作范围
  3. 创建工作分解结构 WBS
  4. 范围确认：让项目干系人确认项目范围是否正确。检查可交付成果是否得到确认，每个可交付成果是否有里程碑、是否有明确的质量标准，项目范围是否准确及其风险性
  5. 范围控制：当项目范围发生变化时如何控制管理，主要是控制范围变更，对变更因素施加影响，控制变更风险

WBS 的六个层次

层次名称 层次编号 层次描述 层次目的
决策层 1 总项目 工作授权和解除
管理层 2 项目 预算编制
管理层 3 任务 进度计划编制
技术层 4 子任务 ——
操作层 5 工作包 内部控制
操作层 6 努力水平 难以衡量具体工作量的其他工作，如与客户联系

工作分解完成后还要编写 WBS 字典，包括详细内容、WBS 编码、工作说明、负责人、进度里程碑清单。

二、时间（进度）管理

进度管理确保能够在给定的时间内交付产品，有六个过程：

  1. 活动定义：在 WBS 分解的基础上，对最底层的工作包进一步分解为一个个活动
  2. 活动排序：识别各项活动之间的逻辑关系，对活动排序
  3. 活动资源估算：确定各项活动需要什么资源、需要多少、什么时候使用
  4. 活动历时估算：估算完成每项活动所需的具体时间，包括专家判断法、三点估算法、功能点估算法、自上而下估算、自下而上估算
  5. 制定进度计划：确定整个项目在每个阶段应完成哪些活动，采用网络规划技术求出关键路径作为项目工期
  6. 进度控制：实施过程中将实际进展与进度计划比较，有偏差则调整；若影响总工期，采用赶工或快速跟进的方法保证按期完成

关键路径计算

双代号图（PERT 图）类似于前趋图，是有向图，反映活动之间的依赖关系，有向边上标注活动运行时间，但无法反映并行关系。

概念 含义
最早开始时间 ES 取所有前驱活动最早完成时间 EF 的最大值
最早完成时间 EF ES + 活动本身时间 DU
关键路径（项目总工期） 项目中耗时最长的一条线路
最晚完成时间 LF 取后续活动最晚开始时间的最小值
最晚开始时间 LS LF - 活动本身时间 DU
松弛时间（总时差） 最晚开始时间 - 最早开始时间（或 LF - EF），即该活动最多可以晚开始多少天
虚路径 用虚线表示的路径，既不消耗资源也不消耗时间，仅用于表示依赖关系

单代号图（前导图）用方框表示活动，框内按「ES、持续时间、EF、活动编号、LS、总时差、LF」的约定标注。

甘特图又称横道图，横轴表示时间、纵轴表示活动，以时间顺序表示活动，能反映活动间的并行关系，但无法反映依赖关系，因此难以清晰确定关键任务和关键路径。时标网络图也可用于计算关键路径，当题目还涉及成本、人员等多个条件限制时常需要画时标网络图求解。

三、成本管理

  1. 成本估算：与进度管理中的活动资源估算一起进行。包括自顶向下的估算（先确定总成本再向下分解到每个工作包，又称类比估算法，要求估算人有类似项目经验）、自底向上的估算（从工作包开始一层层向上估算总成本，要求估算人十分了解项目细节）、差别估算法（上述两种方法的综合，与类似项目比较确定相同部分与不同部分，对不同部分重点估算）
  2. 成本预算：把估算成本分散到 WBS 的每个工作包中建立总体预算成本；把每个工作包分配到的成本二次分配到具体活动上；确定每项成本预算支出的时间计划
  3. 成本控制：与进度控制类似，在项目实施过程中把每个时间点消耗的成本与计划成本比较并调整

挣值分析中的基本量：PV 是计划消耗成本，AC 是实际消耗成本，EV 是已完成工作量的费用。

  • 进度偏差 SV = EV - PV，SV < 0 表示进度拖延，SV > 0 表示进度超前
  • 成本偏差 CV = EV - AC，CV < 0 表示成本超支，CV > 0 表示成本节约

其他概念：管理储备是风险预留基金，用于防止未来风险发生，不包含在预算内；零基准预算指在预算过程中不用以前相似项目来估计成本，而是从 0 开始预计项目成本，估算准确、可以避免浪费。

四、质量管理

质量是软件产品特性的综合，表示软件产品满足明确需求（基本需求）或隐含需求（期望需求）的能力。质量管理是确定质量方针、目标和职责，并通过质量计划、质量控制、质量保证和质量改进来实现的所有管理职能的全部活动。

过程 说明
质量规划 识别项目及其产品的质量要求和标准，并书面描述项目将如何达到这些要求和标准
质量保证 一般每隔一定时间（如每个阶段末）进行，主要通过系统的质量审计（软件评审）和过程分析来保证项目质量
质量控制 实时监控项目的具体结果，判断是否符合质量标准，制订有效方案消除产生质量问题的原因

一定时间内质量控制的结果也是质量保证的质量审计对象；质量保证的成果又可以指导下一阶段的质量工作。

五、配置管理

基本概念

  • 基线：软件开发过程中特定的点，是项目生存期各开发阶段末尾的特定点，又称里程碑，反映阶段性成果。分为功能基线（系统规格说明）、分配基线（软件规格说明）、产品基线（软件产品所有配置项）、发行基线（交付给外部客户）、构造基线（企业内部使用）
  • 配置项：配置管理的基本单位。软件开发过程中的所有文档、代码、工具都可作为配置项，分为环境类、定义类、设计类、编码类、测试类、维护类六种
  • 检查点：在规定的时间间隔内对项目进行检查，比较实际与计划的差异并调整
  • 里程碑：完成阶段性工作的标志

软件配置管理是贯穿整个软件生存周期的技术，主要功能是控制软件生存周期中软件的改变、减少各种改变造成的影响、确保软件产品质量，包括编制配置管理计划、配置标识、配置控制、配置状态报告、配置评价、发行管理和交付等活动。

版本控制

配置项有三个状态：草稿、正式、修改。

状态 版本号格式 规则
草稿 0.YZ YZ 范围为 01～99，随着草稿不断完善应递增，初值和增幅由开发者把握
正式 X.Y X 为主版本号（1～9），Y 为次版本号（1～9），第一次正式发布时版本号为 1.0
修改 X.YZ 修改配置项时一般只增大 Z 值，X.Y 保持不变

版本升级幅度较小时一般只增大 Y 值，X 值保持不变；只有升级幅度较大时才允许增大 X 值。

变更控制

变更控制需要用到基线和配置数据库的概念，配置数据库分为三种：开发库（动态库、程序员库、工作库）、受控库（主库、系统库）、产品库（备份库、静态库、软件仓库）。

变更控制流程：

  1. 变更申请：所有变更请求应由书面申请书提出
  2. 变更评估：对变更的影响范围、经济技术可行性进行分析
  3. 变更决策：决定变更是否实施，若拒绝要给出理由，若实施则给出方案
  4. 变更实施：由管理者指定的工作人员在受控状态下实施
  5. 变更验证：由配置管理人员对变更结果进行评价，判断与预期是否相符
  6. 沟通存档：将变更后的内容通知可能受影响的人员，并把变更记录汇总到文档中

六、风险管理

风险分为三类：

  • 项目风险：威胁到项目计划，可能拖延进度、增加成本，如预算、进度、人员、资源、利益相关者、需求等方面的潜在问题
  • 技术风险：威胁到要开发软件的质量和交付时间，如设计、实现、接口、验证和维护等方面的问题，还包括规格说明的歧义性、技术不确定性、技术陈旧以及前沿技术
  • 商业风险：威胁到要开发软件的生存能力，包括市场风险（开发了没人真正需要的产品）、策略风险（产品不再符合公司商业策略）、销售风险（销售部门不知道怎么卖）、管理风险（失去高级管理层支持）、预算风险（没有得到预算或人员保证）

风险管理过程：

  1. 风险管理计划编制
  2. 风险识别：识别已知和可预测的风险，确定来源、产生条件、特征，形成风险列表
  3. 风险定性分析：对已识别风险排序，确定风险可能性与影响、优先级和类型
  4. 风险定量分析：进一步了解风险发生的可能性和后果严重程度，包括灵敏度分析、期望货币价值分析、决策树分析、蒙特卡罗模拟
  5. 风险应对计划编制：对每个风险制定应对措施，消极风险采用避免、转移、减轻策略，积极风险采用开拓、分享、强大策略
  6. 风险监控：监控风险计划执行，检测残余风险，识别新风险，评价计划的有效性

风险曝光度 = 风险发生的可能性 × 风险发生会带来的损失。
