摘要：本文梳理上午考试的补充章节嵌入式技术，包括冯诺依曼结构与哈佛结构的区别、嵌入式微处理器的四类、多核处理器与调度、嵌入式软件分类与板级支持包、实时操作系统的特点，以及交叉编译与交叉调试的开发流程。

一、嵌入式微处理器

体系结构

冯诺依曼结构（普林斯顿结构）：把程序指令存储器和数据存储器合并在一起，程序和数据共用一个存储空间，程序指令存储地址和数据存储地址指向同一个存储器的不同物理位置；采用单一的地址及数据总线，指令和数据的宽度相同。处理器执行指令时先从存储器取出指令解码，再取操作数执行运算，即使单条指令也要耗费几个甚至几十个周期，高速运算时传输通道上会出现瓶颈效应。

哈佛结构：一种并行体系结构，主要特点是把程序和数据存储在不同的存储空间中，即程序存储器和数据存储器是两个相互独立的存储器，每个存储器独立编址、独立访问，对应两套独立的地址总线和数据总线。分离的总线允许在一个机器周期内同时获取指令字和操作数，从而提高执行速度，使数据吞吐率提高一倍，但这不意味着可以在一个机器周期内多次访问存储器。

嵌入式微处理器的分类

嵌入式硬件系统一般由嵌入式微处理器、存储器、输入输出部分组成，其中微处理器是核心，通常由控制单元、算术逻辑单元、寄存器三部分组成。

按字长宽度可分为 4 位、8 位、16 位、32 位和 64 位，一般把 16 位及以下的称为嵌入式微控制器，32 位及以上的称为嵌入式微处理器。按系统集成度可分为一般用途型微处理器和单芯片微控制器。按用途分类：

类型 特点
嵌入式微控制器 MCU 典型代表是单片机，片内集成 ROM/EPROM、RAM、总线逻辑、定时计数器、看门狗、I/O、串口、A/D、D/A、Flash、EEPROM 等，最大特点是单片化，体积小、功耗和成本低、可靠性高，适合控制，是嵌入式系统工业的主流
嵌入式微处理器 MPU 由通用计算机的 CPU 演变而来，具有 32 位以上处理能力和较高性能，价格相应较高。实际应用中只保留与嵌入式应用紧密相关的功能硬件，以最低功耗和资源实现特殊要求，常见有 ARM、MIPS、PowerPC
嵌入式数字信号处理器 DSP 专门用于信号处理，在系统结构和指令算法上做了特殊设计，采用哈佛结构、流水线处理，在数字滤波、FFT、谱分析等仪器上应用广泛
嵌入式片上系统 SoC 追求产品系统最大包容的集成器件，最大特点是实现软硬件无缝结合，直接在处理器片内嵌入操作系统代码模块

DSP 的特点：多总线结构允许 CPU 同时进行指令和数据访问，可实现流水线操作；采用哈佛体系结构，程序和数据空间分开；运算特点是乘加及反复相乘求和（乘积累加）；设置了硬件乘法/累加器，能在单个指令周期内完成乘法加法运算。

多核处理器

多核是把两个或更多的微处理器内核封装在一起、集成在一个电路中，是单枚芯片，可直接插入单一的处理器插槽。与多 CPU 相比，多核很好地降低了系统的功耗和体积，由操作系统软件进行调度，多进程、多线程并发都可以。

由于把多个运算核封装在一个芯片上，节省大量晶体管和封装成本，显著提高处理器性能，兼容性好、系统升级方便。

两个或多个内核工作协调的实现方式：

  • 对称多处理技术：把两颗完全一样的处理器封装在一个芯片内，达到双倍或接近双倍的处理性能，节省运算资源
  • 非对称处理技术：两个处理内核彼此不同，各自处理和执行特定功能，在软件协调下分担不同的计算任务

多核 CPU 的调度算法有全局队列调度和局部队列调度两种：全局队列调度由操作系统维护一个全局任务等待队列，有 CPU 空闲时就从全局队列选取就绪任务执行，CPU 核心利用率高；局部队列调度为每个内核维护一个局部任务等待队列，内核空闲时从自己的队列中选取任务执行，优点是无须在多个 CPU 之间切换。

二、嵌入式软件与操作系统

嵌入式软件

嵌入式软件除了具有通用软件的一般特性，还有规模较小、开发难度大、实时性和可靠性要求高、要求固化存储等特点，分为三类：

  • 系统软件：控制和管理嵌入式系统资源、为应用提供支持的软件，如设备驱动程序、嵌入式操作系统、嵌入式中间件
  • 应用软件：上层软件，定义嵌入式设备的主要功能和用途，负责与用户交互，一般面向特定应用领域，如飞行控制软件、手机软件、地图
  • 支撑软件：辅助软件开发的工具软件，如系统分析设计工具、在线仿真工具、交叉编译器

板级支持包 BSP

BSP 又称硬件抽象层 HAL，介于主板硬件和操作系统的驱动层程序之间，一般认为是操作系统的一部分，为上层驱动程序提供访问硬件设备寄存器的函数包。BSP 是相对于操作系统而言的，不同操作系统的 BSP 实现的功能相同但写法和接口定义完全不同。

BSP 的主要功能：单板硬件初始化（主要是 CPU 初始化，为整个软件系统提供底层硬件支持）；为操作系统提供设备驱动程序和系统中断服务程序；定制操作系统的功能，提供实时多任务的运行环境；初始化操作系统。

BSP 的两个特点：硬件相关性（为操作系统提供操作和控制具体硬件的方法）、操作系统相关性（不同操作系统有特定的硬件接口形式）。

BSP 主要包括引导加载程序 BootLoader 和设备驱动程序。BootLoader 是嵌入式系统加电后运行的第一段软件代码，在操作系统内核运行之前运行，用于初始化硬件设备、建立内存空间映射图，其初始化过程包括：

  1. 片级初始化：初始化微处理器，设置核心寄存器和控制寄存器、核心工作模式及局部总线模式，是纯硬件初始化过程
  2. 板级初始化：设置各种寄存器完成微处理器以外的其他硬件初始化，如 LED 显示设备、定时器、中断控制寄存器、串口通信、内存控制器、内存地址映射，同时包含软件和硬件的初始化过程
  3. 加载内核（系统级初始化）：把操作系统和应用程序的映像从 Flash 复制到内存，然后跳转到内核第一条指令继续执行

设备驱动程序是一组库函数，用来对硬件进行初始化和管理，并向上层软件提供良好的访问接口，基本功能包括硬件启动、硬件关闭、硬件停用、硬件启用、读操作、写操作。

嵌入式操作系统

嵌入式操作系统 EOS 负责嵌入式系统全部软硬件资源的分配和任务调度，控制协调并发活动，通常包括底层驱动软件、系统内核、设备驱动接口、通信协议、图形界面等。常见的有 μC/OS-II、嵌入式 Linux、Windows Embedded、VxWorks，以及智能手机和平板上的 Android、iOS。

嵌入式操作系统的特点：

  1. 系统内核小：嵌入式系统资源相对有限，内核比传统操作系统小得多
  2. 专用性强：软硬件结合非常紧密，一般要针对硬件进行移植，同一品牌同一系列产品也需要根据硬件变化不断修改
  3. 系统精简：一般没有系统软件和应用软件的明显区分
  4. 高实时性：高实时性系统软件是基本要求，软件要求固态存储以提高速度，代码要求高质量和高可靠性
  5. 多任务的操作系统：为了合理调度多任务、利用系统资源以及和专用库函数接口，需要自行选配操作系统开发平台

嵌入式实时系统要求系统在投入运行前即具有确定性和可预测性：可预测性指系统运行之前其功能、响应特性和执行结果是可预测的；确定性指系统在给定的初始状态和输入条件下，在确定的时间内给出确定的结果。对嵌入式实时系统失效的判断不仅依赖运行结果数值是否正确，也依赖提供结果是否及时。

实时操作系统 RTOS 的特点是提供及时响应和高可靠性，分硬实时（要求在规定时间内必须完成操作，由操作系统设计时保证）和软实时（按任务优先级尽可能快完成即可）。

实时操作系统的三个特征：

  • 高精度计时系统：计时精度是影响实时性的重要因素
  • 多级中断机制：确保对紧迫程度较高的实时事件及时响应和处理
  • 实时调度机制：一是在调度策略和算法上保证优先调度实时任务，二是建立更多「安全切换」时间点

三、嵌入式软件设计

开发流程

嵌入式软件开发采用宿主机和目标机的模式：宿主机是普通 PC 上构建的开发环境，一般需要配置交叉编译器，借助宿主机环境使用交叉编译器进行目标编译和代码生成，同时借助仿真器或网络进行目标机程序调试；目标机可以是嵌入式系统的实际运行环境，也可以是能替代实际运行环境的仿真系统。

开发方式是：在宿主机上建立开发环境、完成编码和交叉编译，然后在宿主机和目标机之间建立连接，将目标程序下载到目标机中进行交叉调试和运行。

交叉编译与交叉调试

交叉编译是在一个平台上生成可以在另一个平台上执行的代码。由于不同体系结构有不同的指令系统，不同 CPU 需要相应的编译器，交叉编译就像翻译一样把相同程序代码翻译成不同 CPU 对应的可执行二进制文件。因为通用计算机资源丰富、集成开发环境和调试工具方便，而嵌入式系统资源紧缺无法运行编译工具，所以需要借助宿主机编译出目标机的可执行代码。

交叉调试与通用软件调试的差别在于：通用软件调试中调试器与被调试程序运行在同一台计算机上；嵌入式开发中调试器仍运行在宿主机的通用操作系统上，被调试进程运行在目标机的嵌入式操作系统中，两者通过串口或网络通信，调试器可以控制、访问被调试进程，读取其当前状态并改变其运行状态。

常用开发工具

阶段 工具
编码 编辑器。任何文本编辑器都可编写源代码，集成开发环境提供功能强大的编辑器，常见独立编辑器有 UE、SourceInsight、vim
交叉编译 编译器 gcc。它是常用的交叉编译器，支持非常多的宿主机/目标机组合，包含预处理器、编译器、汇编器、连接器等组件
交叉调试 调试器 gdb。调试器运行在宿主机上，被调试程序运行在目标机上，通过串口、并口、网络、JTAG 等方式建立联系，目标机上一般有调试器的代理配合完成调试
